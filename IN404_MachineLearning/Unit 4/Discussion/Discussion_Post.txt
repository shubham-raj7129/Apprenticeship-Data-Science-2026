Handling missing data is one of the most fundamental challenges in machine learning, and it is something I have already encountered firsthand in this course. In our Unit 3 and Unit 4 code, the very first thing we did after loading the IN404_Reviews.csv dataset was replace all NaN values with the string "none" and then filter out those rows entirely — reducing our dataset from 958 reviews down to just 363 usable ones. That single step removed over 60% of our data, which made me realize how significant the missing data problem really is. According to Emmanuel et al. (2021), missing data is pervasive in real-world datasets and arises from multiple causes, including sensor failures, human error during data entry, participant non-response in surveys, and system crashes during data collection. If these gaps are not handled properly, the resulting models can produce biased predictions, reduced statistical power, and misleading accuracy scores that give a false sense of confidence.

Advantages of Handling Missing Data and Disadvantages If Not Handled

There are clear advantages to addressing missing data before training a model. First, it improves model accuracy by ensuring the algorithm learns from complete, representative information rather than gaps or placeholders. Second, it reduces bias — if the missing values are not random (for example, if dissatisfied customers are less likely to leave a written review), then ignoring the missingness introduces a systematic skew into the model's predictions. Third, properly handled data leads to better generalization, meaning the model performs more reliably on new, unseen data. On the other hand, the disadvantages of not handling missing data are serious. Many machine learning algorithms, including scikit-learn's logistic regression, cannot process NaN values at all and will throw errors if missing data is present. Even algorithms that tolerate missing values may produce skewed results — for instance, computing a mean on incomplete data underestimates or overestimates the true central tendency. In our own Unit 4 code, if we had not filtered out the empty reviews, the count vectorizer would have tried to tokenize blank strings, producing meaningless features that would degrade the model's ability to distinguish 1-star from 5-star reviews.

Techniques for Handling Missing Data

Several techniques exist for handling missing data, and the right choice depends on the nature and extent of the missingness. The simplest approach is deletion — either listwise deletion, which drops any row with at least one missing value (what our code does with dropna() or manual filtering), or pairwise deletion, which uses all available data for each specific calculation. Deletion is appropriate when the missing data is random and the remaining dataset is still large enough to train on, but it risks losing valuable information if a large proportion of rows are incomplete. Imputation is the alternative: replacing missing values with estimated ones. Common strategies include mean imputation (replacing NaN with the column average), median imputation (more robust to outliers), and mode imputation (used for categorical data). More advanced methods include K-Nearest Neighbors (KNN) imputation, which estimates missing values based on the most similar complete observations, and Multiple Imputation by Chained Equations (MICE), which generates multiple plausible values to account for uncertainty (Emmanuel et al., 2021). In pandas, the practical tools for these operations are straightforward: isnull() and notnull() detect missing values, dropna() removes them, fillna() replaces them with a specified value or strategy, and replace() swaps specific values like our code's reviews.replace(['NaN', np.nan], 'none').

Handling NaN/NULL Values, Formatting Data, and Adding Columns

Beyond simply removing or filling missing values, data formatting is an important part of the preparation process. This includes converting data types — for example, ensuring a column that should be numeric is not stored as a string, or parsing a date column into a proper datetime format so it can be used for time-based analysis. Adding new columns based on existing data is another valuable technique. In our Unit 3–4 code, we added a sentiment column by applying TextBlob's polarity function to the Review_Text column: reviews['sentiment'] = reviews.Review_Text.apply(detectSentiment). This created an entirely new feature from existing data, giving the model additional information without requiring any external data source. Similarly, in Unit 4, the final reduced model combined Review_Text, Review_Title, sentiment, and sentiment_title into a focused 4-feature dataset that achieved the highest cross-validated accuracy (88.37%). These formatting and feature-engineering steps are just as important as handling missing values — they transform raw data into a shape that the learning algorithm can actually use.

Three Visualizations and Their Use Cases

Visualizations play a critical role in communicating the results of machine learning models and in understanding the data before modeling begins. The first visualization I would highlight is the heatmap. Heatmaps are effective for (a) visualizing missing data patterns across a dataset — libraries like missingno in Python generate heatmaps that show exactly where and how frequently values are missing, making it easy to spot whether missingness is random or systematic, and (b) displaying correlation matrices between features, which helps in feature selection by revealing which variables are strongly related and which are redundant. The second visualization is the box plot. Box plots are useful for (a) detecting outliers in numerical features before and after imputation — if imputed values create unusual distributions, the box plot makes this immediately visible, and (b) comparing distributions across categories, such as our Unit 3 box plot of sentiment polarity grouped by star rating, which showed that higher stars generally corresponded to higher polarity but with significant overlap. The third visualization is the bar chart. Bar charts are effective for (a) comparing class distributions — in our dataset, a bar chart revealed that 5-star reviews far outnumbered 1-star reviews, exposing the class imbalance problem, and (b) presenting model accuracy scores side by side across different configurations, which is exactly what we need in Unit 4 to show how the 15 different vectorizer and TF-IDF models performed relative to each other and the null model.

Two Examples of Handling Missing Data Effectively

To conclude, I want to highlight two real-world examples where handling missing data made a meaningful difference. The first is in healthcare: when building a predictive model for disease diagnosis, patient records frequently have missing lab values because not every test is ordered for every patient. Rather than discarding all incomplete records (which could eliminate the majority of the dataset), researchers often use median imputation or KNN imputation to fill in the gaps, preserving the dataset size while maintaining reasonable estimates for the missing values. The second example is exactly what we did in this course — in our e-commerce review analysis, we dropped rows where the Review_Text field was empty because a sentiment classifier cannot learn anything from a blank string. This was a case where deletion was the right choice: there was no meaningful way to impute the content of a missing review, so removing those rows was both practical and honest. Both examples illustrate the same principle: the technique must match the reason the data is missing and the requirements of the model being trained.
